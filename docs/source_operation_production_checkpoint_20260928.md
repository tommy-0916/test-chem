## What the producer now does

- The model proposes an operation, its participating material and source quotation. For a uniquely located affirmative split or transfer on one identifiable parent, the program constructs the typed operation segment, material relation and lineage relation from that one event. It can create child ports from an explicit split count or assign missing child instance symbols; the existing ID canonicalizer then scopes internal IDs to the document and experimental group. The parent's `material_id` continues across same-material children, while each child has its own instance ID.
- A split count determines the number of child instances, **not** their individual amounts. The relation uses `runtime_measurement_required`; it creates no per-child allocation or output quantity. Concentration and portion-count units remain invalid as output material amounts.
- The constructed output-state fact is an **unreviewed convention candidate** tied to the operation quotation. Existing source binding, compiler, scientific audit and V2 reconstruction still decide whether the proof is valid. The original model response is retained separately, with generated-field audit rows; no signed or published object is rewritten.
- The producer abstains on negation, wrong operation subject, uncertain parent, mismatched split count, duplicate child instances, unrelated child quotations, cross-arm reuse of an upstream instance, and conflicting explicit model topology. A missing material origin remains pending; being the first proposed graph step does not establish external inventory.
- A bounded source-operation inventory now identifies uniquely locatable split/transfer mentions in the enumerated PDF group. The initial prompt includes these **source mentions, not approvals**. After model generation, the producer checks whether a mention on a proposed material is actually represented by a matching graph operation **value**, operation fact and participant input. An operation appearing only in another field's excerpt is reported as `source_operation_unrepresented`. This check also runs after local revision. It does not insert a missing step or change a previously passing scientific claim.
- The inventory is a bounded lexical observation, not proof that every operation in the source has been found. Multi-event, unknown-count and source-binding ambiguity remain explicit, scoped unresolved diagnostics when relevant to the proposed material; they are not treated as approved split or transfer semantics.
- For a source-backed split or transfer, the unsigned producer may replace an overlong operation, directly related parent input or unitless count fact quotation with a uniquely bound, same-event subquote. The subquote must occur within the original quotation and retain the fact's literal value and role. The transformation records both quotations and does not change the model's fact value, entity or step. An unsupported top-level split `count` is consumed only when it agrees with the source operation and its unitless count fact; child cardinality then carries the count without inventing child amounts. The raw model response remains intact.
