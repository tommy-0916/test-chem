## 方向纠正：原文事实与机器语义分层

当前 `route_group_compiler.py` 把路线签名、操作、每个物料端口的 `name/material_id/state` 都放入必须有逐字 route fact 的路径集合；字符串事实要求原文子串，数值事实要求非空单位；通过的事实又统一转为 `paper_explicit`。这会把来源事实、受控映射和程序标识混为一类。A01 重放出现的 22 个 `material_id` 缺口是可复现的症状，不能靠为 `solution_a` 一类程序标识伪造论文摘录解决。

下一个最小设计切片应沿用现有 `ProvenanceV2`、受控状态词表、convention 与 V2 发布门：

| 字段来源 | 应保存的依据与验证 |
| --- | --- |
| 试剂、原文量值、时间、温度等 | 固定 PDF 摘录、实验组、量值/单位和物料归属；可标 `paper_explicit`。 |
| 操作和状态的规范化 | 原词、受控映射规则及版本、适用条件；保留到原文的回链，不把规范标签冒充原文原词。 |
| convention 状态或谱系 | 已有规则 ID、前置条件和原始事实；不由 convention 生成无依据数值。 |
| 计算或换算 | 输入事实、公式、量纲及舍入规则；区分无量纲 pH/次数/比例、浓度和物质的量。 |
| `material_id`、步骤/批次 ID | 程序生成，验证唯一性、引用闭合和物料图一致性；不要求论文写出内部 ID。 |
| 实际产量、剩余量、反馈加料 | `runtime_pending` 及解析路径，待真实测量或控制反馈；不得在规划时猜值。 |

改变这一层时需同时核对 `route_group_compiler.py`、`route_group_fact_receipt.py`、`chem_agent_contracts/v2.py`、`route_science.py` 和 Research 发布门的逐字段证据一致性。不能只删掉某个逐字判断，使转换后的字段全部无条件变成 `paper_explicit`。

实施时先做**只诊断的字段分类**：`paper_literal / controlled_mapping / convention / derived / generated_id / runtime`。分类尚未接入逐字段 provenance 和现有发布核验之前，非原文字段应报告 `semantic_binding_pending`，不得凭“分类成功”直接放行。本次新增的 `required_graph_fact_missing` 仍复制了旧编译器的逐字事实范围，它能暴露冲突，却不是六类依据的最终判定。

## 实施顺序

1. **先定字段类别并修一条真实语义链。** 选真实原文中“收集沉淀/solution A/一个有单位的前驱体用量”及另一材料体系的同类例子，验证原词、映射/规则、内部 ID、物料关系和最终 V2 provenance 各自不丢。补同义表达、同句多物料量值、无量纲数值、单位换算和不同 PDF 分块的正反例。保留未获支持数值阻断。
2. **再收敛局部修订。** 让提案生产器按上述字段类别给出精确反馈，只修失败字段或受影响组；已过字段在同来源/解析版本下复用。缺必需字段、改变已通过事实、跨组借证、删除图约束和超预算均明确阻断。用两种版式、两种化学体系做新生成与无模型回放。
3. **八题并行做廉价的任务覆盖和路线预检。** A01/A02/B01/B02/C01/C02/D01/D02 各自产出因素、对照、时间点、观测、当前 Stage、候选路线和缺证据/审阅/设备依赖；先看广度，再选择真实路线深入。不得复制 A01 四臂模板或要求一篇论文覆盖整项研究。
4. **把独立科学核验接成可完成的工作流。** 明确自动可核验范围、独立审阅者/服务的输入与回执、歧义升级；自动来源和字面回执不得冒充人工化学审阅。
5. **逐题通过 Research→Device 本地前向门。** 用真实路线生成能力需求并核对真实工作站合同，利用 FeasibilityFeedback 只在任务允许且有证据的范围内修订；平台合同缺失单列，不靠 Agent 猜能力。直到这些门通过前，不恢复连续 A01 重跑。
6. **最后验证观测驱动的后续 Stage。** 将真实观测绑定样品、处理历史和条件，做质量检查，推进时间序列、反应前后及产物分析；模拟/预期结果不算科学结论。

本快照用于保存进度和纠偏；它不是八题验收报告，也不是执行授权。
